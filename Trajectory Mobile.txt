● The Android app (engines/android-app/) uses this architecture:

Pattern: Custom Manager-Coordinator (not standard MVVM/MVI)                   
- WorkflowManager 
— central singleton managing all workflow lifecycle (loaded, active, completed) via StateFlow<ManagerState>
- WorkflowCoordinator 
	— wraps the KMP engine per-workflow, bridging engine state to reactive StateFlow

UI Layer: Jetpack Compose + Material 3
  - Bottom navigation with 5 screens: Home, Active, Overview, History, Settings
  - Compose Navigation (NavController) with single-top and state restoration
  - Dynamic form rendering via an element registry pattern (TextInput, Checkbox, Image, Video, Timer, etc.)
  - Adaptive layout using WindowWidthSizeClass

Engine Integration: KMP (Kotlin Multiplatform)
  - The KMP engine at engines/kmp-engine/ is imported as a direct Gradle project dependency (:engine)
  - Native Kotlin class usage — WorkflowEngine, WorkflowState, UserAction etc.
  - No JSON-in/JSON-out facade needed (that's for the JS target)

Persistence: Room Database
  - 3 entities: LoadedWorkflow, ActiveWorkflow, CompletedWorkflow
  - Debounced saves (300ms) from coordinator state changes

State Management: StateFlow + collectAsState()
  - Single source of truth in WorkflowManager.state
  - All Compose screens observe via collectAsState()
  - Shared resource managers for cross-workflow data

Key Libraries: 
	Compose BOM 2025.01.01, 
	Room 2.6.1, 
	Media3/ExoPlayer 1.5.1, 
	Coil3 3.0.4, 
	Kotlinx Serialization 1.7.3,
	Coroutines 1.9.0

Basic Model of Properties and Parameters:
1) Steps use Value Properties, input parameters, and output parameters to pass data back and forth. 
2) Step's input parameter values can be a fixed text string (defined in the workflow), copied from a Workflow Input Parameter, copied from a Workflow Value Property, or copied from an Environment Value Property. 
3) Step's output parameter values can written to a Workflow Output Parameter, written to a Workflow Value Property, or written to an Environment Value Property. 
4) Environment Steps use input parameters internally to send to Environment Actions.
5) Environment Steps receive output parameters from Environment Actions.
6) UI steps can use Input parameters as place holder source in text box.   
7) UI steps can put user entered info (text, radio, checkbox) into an output parameter of the step. 
8) Child workflows pick up their input parameter values from the parent step's input parameters.
9) Parent steps pick up their output parameter values from the child workflow's output parameters.
