# Trajectory Mobile — Rich Text Rendering Specification

## Overview

This specification describes how Trajectory Mobile renders HTML rich text content in Text and Header form elements, and replaces parameter placeholder chips with runtime values. It covers the export schema, supported HTML tags, the parameter chip replacement algorithm, the plain text fallback, and container-level element styling. See **UISpec.md section 3 (Form Rendering)** for device layout and element positioning context.

---

## 1. Export Schema

### 1.1 RichTextContent Wrapper

Text and Header elements in `form_layout_config.elements[]` export their content as a `RichTextContent` object rather than a raw string. The `{ content, plainText }` wrapper is the export format received by the mobile runtime.

```json
{
  "type": "text",
  "content": {
    "content": "<p>Patient <span data-param-chip=\"patient.name\"></span>, please confirm your blood pressure reading of <span data-param-chip=\"patient.bloodPressure\"></span>.</p>",
    "plainText": "Patient <patient.name>, please confirm your blood pressure reading of <patient.bloodPressure>."
  },
  "fontSize": 16,
  "color": "#333333",
  "align": "left",
  "x": 20,
  "y": 60,
  "width": 335,
  "height": 60
}
```

### 1.2 RichTextContent Interface

```typescript
interface RichTextContent {
  content: string // HTML string with full formatting and parameter chip spans
  plainText: string // Stripped plain text; <name.key> syntax preserved for parameter placeholders
}
```

| Field       | Type     | Semantics                                                                                                                                                                                   |
| ----------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `content`   | `string` | Full HTML string. Contains formatting tags (`<strong>`, `<em>`, etc.) and parameter chip spans (`<span data-param-chip="..."></span>`). This is the primary rendering field.                |
| `plainText` | `string` | Plain text fallback with all HTML tags stripped. Parameter chip placeholders are preserved as `<name.key>` angle-bracket syntax (not HTML spans). Use when HTML rendering is not available. |

### 1.3 Store vs. Export Format

The Trajectory MD designer stores Text and Header content as a raw HTML string in the Zustand store. The export pipeline wraps it in `{ content, plainText }` at export time. The import pipeline unwraps it back to a raw HTML string. The mobile runtime always receives the wrapped `RichTextContent` format.

### 1.4 Header Element

The `header` element has the same `content: RichTextContent` structure as `text`:

```json
{
  "type": "header",
  "content": {
    "content": "<p><strong>Patient Check-In</strong></p>",
    "plainText": "Patient Check-In"
  },
  "fontSize": 24,
  "fontWeight": "bold",
  "align": "center",
  "x": 20,
  "y": 20,
  "width": 350,
  "height": 50
}
```

All rendering behavior described in this specification applies equally to both `text` and `header` elements.

## 2. HTML Tag Support

### 2.1 Required Tags

The `content` field is generated by Tiptap v3's HTML serializer. The mobile runtime must support the following HTML constructs produced by this editor:

| HTML                                       | Semantics             | Notes                                     |
| ------------------------------------------ | --------------------- | ----------------------------------------- |
| `<p>`                                      | Paragraph block       | All text content is wrapped in `<p>` tags |
| `<strong>`                                 | Bold text             | Inline bold emphasis                      |
| `<em>`                                     | Italic text           | Inline italic emphasis                    |
| `<u>`                                      | Underline text        | Inline underline decoration               |
| `<span style="font-family: ...">`          | Custom font family    | Inline style attribute                    |
| `<span style="font-size: ...pt">`          | Custom font size      | Size in points, inline style attribute    |
| `<span style="color: ...">`                | Custom text color     | CSS color value, inline style attribute   |
| `<span data-param-chip="name.key"></span>` | Parameter placeholder | Empty span body — see section 3           |

### 2.2 Nested Spans

Multiple inline styles and the parameter chip may be nested. For example, a bold, red-colored parameter chip might appear as:

```html
<p>
  <strong
    ><span style="color: #cc0000;"><span data-param-chip="patient.name"></span></span
  ></strong>
</p>
```

The runtime must apply all applicable styles from the nesting context when rendering the resolved parameter value.

### 2.3 Scope

Only the tags listed in section 2.1 are produced by the Trajectory MD designer. The runtime is not required to support other HTML tags, though graceful degradation (render as plain text) is recommended for any unexpected tags.

## 3. Parameter Placeholder Rendering

### 3.1 Chip Format

Parameter placeholders are exported as empty `<span>` elements with a `data-param-chip` attribute:

```html
<span data-param-chip="name.key"></span>
```

- The `data-param-chip` attribute contains the full `name.key` parameter reference (e.g., `"patient.name"`, `"intake.lastBloodPressure"`).
- The span body is **empty** in the export. In the Trajectory MD designer, the chip label is rendered via CSS `::before` pseudo-element. The mobile runtime must replace the empty span with the resolved parameter value.

### 3.2 Replacement Algorithm

```
function renderRichTextContent(htmlContent, resolvedInputParameters):
  // 1. Parse the HTML content into a document tree
  dom = parseHTML(htmlContent)

  // 2. Find all parameter chip spans
  chipSpans = dom.findAll("span[data-param-chip]")

  // 3. Replace each chip span with the resolved value
  for each chipSpan in chipSpans:
    paramRef = chipSpan.getAttribute("data-param-chip")
    // e.g., "patient.name"

    // 4. Resolve the parameter from the workflow's input parameter map
    // See ExecutionEngineSpec.md section 6.1 for the full resolution algorithm
    resolvedValue = resolvedInputParameters.lookup(paramRef)

    if resolvedValue is not null and resolvedValue is not undefined:
      // 5a. Replace the empty span with a text node containing the resolved value
      //     Preserve the span's surrounding styling context (parent styles remain)
      chipSpan.replaceWithText(resolvedValue)
    else:
      // 5b. Parameter not found — show the raw reference syntax as a fallback
      chipSpan.replaceWithText("<" + paramRef + ">")

  // 6. Render the resulting HTML with all formatting intact
  return renderHTML(dom)
```

### 3.3 Styling of Resolved Values

When a chip span is replaced with the resolved text, the replacement inherits the styling context of the surrounding elements. If the chip span is inside a `<strong>` or a `<span style="color:...">`, the resolved text should render with those styles applied.

### 3.4 Resolution Timing

Parameter chip replacement occurs when the form is first rendered, at the same time as form default resolution (see ParameterMappingSpec.md section 2.1). Text and Header elements are static display elements — they do not re-render when parameter values change during step execution. The resolved values shown are those available at step start.

## 4. Plain Text Fallback

### 4.1 When to Use

The `plainText` field is a fallback for runtimes or contexts that cannot render HTML. The primary rendering path should always use the `content` (HTML) field. Use `plainText` only when:

- The rendering environment does not support HTML (e.g., a notification system, an accessibility text reader, or a log output)
- HTML parsing fails or is unavailable

### 4.2 Plain Text Format

In the `plainText` field, parameter placeholders appear as `<name.key>` angle-bracket syntax — not as HTML spans. This is distinct from the HTML chip format:

| Format                 | Where             | Example                                        |
| ---------------------- | ----------------- | ---------------------------------------------- |
| HTML chip              | `content` field   | `<span data-param-chip="patient.name"></span>` |
| Plain text placeholder | `plainText` field | `<patient.name>`                               |

Example:

```
"plainText": "Patient <patient.name>, please confirm your blood pressure reading of <patient.bloodPressure>."
```

### 4.3 Plain Text Replacement Algorithm

```
function renderPlainText(plainText, resolvedInputParameters):
  // Find all <name.key> patterns (angle-bracket syntax, not HTML tags)
  // Pattern: < followed by name.key format (word.word) followed by >
  result = plainText

  for each match of pattern /<([a-zA-Z][a-zA-Z0-9_]*\.[a-zA-Z][a-zA-Z0-9_]*)>/g in result:
    paramRef = match.captureGroup(1)  // e.g., "patient.name"
    resolvedValue = resolvedInputParameters.lookup(paramRef)

    if resolvedValue is not null and resolvedValue is not undefined:
      result = result.replace(match.fullMatch, resolvedValue)
    // else: leave the <name.key> placeholder as-is (unresolved)

  return result
```

### 4.4 HTML Entities

The `plainText` field has standard HTML entities decoded by the export pipeline (`&amp;` → `&`, `&lt;` → `<`, `&gt;` → `>`, `&quot;` → `"`, `&#39;` → `'`). The runtime does not need to decode entities in the `plainText` field.

## 5. Element-Level Styling

### 5.1 Container Style Fields

Text and Header elements carry container-level style fields alongside the `content` field. These define the default appearance for the entire element:

| Field        | Type                            | Default (text) | Default (header) | Semantics                                                    |
| ------------ | ------------------------------- | -------------- | ---------------- | ------------------------------------------------------------ |
| `fontSize`   | `number`                        | `16`           | `24`             | Default font size in logical pixels for the element          |
| `fontWeight` | `"normal" \| "bold"`            | `"normal"`     | `"bold"`         | Default font weight for the element                          |
| `color`      | `string`                        | theme default  | theme default    | Default text color as a CSS color string (e.g., `"#333333"`) |
| `align`      | `"left" \| "center" \| "right"` | `"left"`       | `"left"`         | Horizontal text alignment for the element                    |

All fields are optional in the JSON. When absent, use the default values shown above.

### 5.2 Priority: Inline vs. Container

Inline HTML styles within the `content` field override container-level styles for the affected text spans:

- Container styles apply to the element as a whole (the default appearance)
- `<span style="font-size:...pt">` overrides `fontSize` for the spanned text
- `<span style="color:...">` overrides `color` for the spanned text
- `<span style="font-family:...">` adds a font family override for the spanned text
- `<strong>` overrides `fontWeight` to bold for the spanned text

Container-level `align` applies to the entire element and is not overridable by inline HTML in Tiptap's output.
