**1. Create src/manager/types.ts** with these interfaces:

```typescript
interface ManagedWorkflow {
  id: string;              // crypto.randomUUID()
  specOid: string;         // from workflow spec's oid field
  name: string;            // spec.description || spec.oid
  coordinator: WorkflowCoordinator;
  loadedAt: number;        // Date.now()
  status: 'loaded' | 'running';
}

interface ManagerSnapshot {
  workflows: ManagedWorkflow[];
  focusedId: string | null;
  activeCount: number;     // workflows.length
}

interface HistoryEntry {
  id: string;
  specOid: string;
  name: string;
  status: 'completed' | 'abandoned';
  startedAt: number;
  finishedAt: number;
}

type Listener = () => void;
```

Export all types.

**2. Modify src/coordinator/WorkflowCoordinator.ts** -- add a `load()` method that stores spec/mediaMap/environments but does NOT call engine.start(). This supports the "loaded but not started" state from CONTEXT.md decisions. The existing `loadAndStart()` should call `load()` internally then `start()`. Add a public `start()` method that creates the engine and starts it. Refactor so:
- `load(workflow, setup?, mediaMap?, environments?)` stores all args, sets up environments/resourceManager, but does NOT create engine or start
- `start()` creates `new WorkflowEngine(this.workflow, this.engineSetup)` and calls `engine.start()`, then `sync()`
- `loadAndStart()` calls `load()` then `start()` (preserves backward compat)
- `getSpec()` returns the stored workflow spec (needed by manager for OID access)

Keep the existing subscribe/getSnapshot/reset/restart/submitAction signatures unchanged. The snapshot workflowState stays 'IDLE' until start() is called.

**3. Create src/manager/WorkflowManager.ts** class following the exact subscribe/getSnapshot pattern from WorkflowCoordinator:
- Constructor accepts a HistoryStore instance
- `addWorkflow(spec, mediaMap, environments?)` -- creates coordinator, calls coordinator.load() (NOT loadAndStart), creates ManagedWorkflow with status 'loaded', auto-focuses the new workflow, returns the workflow ID. Check for duplicate specOid first -- if found, return `{ duplicateId: string }` instead of adding (let caller handle the prompt UI)
- `startWorkflow(id)` -- calls coordinator.start() on the managed workflow, sets status to 'running'
- `removeWorkflow(id)` -- calls coordinator.reset() (cleanup blob URLs), removes from list, shifts focus to first remaining workflow if the removed one was focused
- `focusWorkflow(id)` -- updates focusedId
- `getCoordinator(id)` -- returns the WorkflowCoordinator for a given workflow ID (or null)
- `getSnapshot()` -- returns cached ManagerSnapshot (new object only on publish)
- `subscribe(listener)` -- returns unsubscribe function
- Manager subscribes to each coordinator's snapshot. In the subscription callback, check if workflowState changed to 'COMPLETED' or 'ABORTED'. If so: create HistoryEntry (use 'completed' for COMPLETED, 'abandoned' for ABORTED), call historyStore.addEntry(), call removeWorkflow(). Use a Set to track coordinator unsubscribe functions for cleanup.

Arrow function properties for subscribe and getSnapshot (stable references for useSyncExternalStore).

- `getSnapshot()` -- returns cached array reference
- `subscribe(listener)` -- returns unsubscribe function
- `getEntryCount()` -- convenience for badge display

Arrow function properties for subscribe and getSnapshot.
