**WorkflowCoordinator additions (src/coordinator/WorkflowCoordinator.ts):**

Add three new methods:

1. `abort(): void` -- For ABANDON command. The engine has no abort method, so handle at coordinator level:
   - If no engine, return
   - Call this.revokeBlobUrls()
   - Set this.engine = null
   - Publish snapshot with workflowState: 'ABORTED', activeSteps: [], keep trace/properties from current snapshot, clear inputParameters/error/mediaMap/stepParams
   - This triggers the manager's auto-history subscription to move workflow to history and remove it

2. `pauseAll(): void` -- For PAUSE command. Iterate all active steps:
   - If no engine, return
   - Get activeSteps from current engine
   - For each step with state === 'EXECUTING', call this.engine.submitAction({ step_oid: step.oid, action: 'pause' }, this.actionIndex++)
   - Call this.sync() once at the end

3. `resumeAll(): void` -- For RESUME command. Iterate all active steps:
   - If no engine, return
   - Get activeSteps from current engine
   - For each step with state === 'PAUSED', call this.engine.submitAction({ step_oid: step.oid, action: 'resume' }, this.actionIndex++)
   - Call this.sync() once at the end

**StateCommandMenu component (src/components/StateCommandMenu.tsx):**
- Props: { workflowId: string | null } -- the focused workflow id
- Get manager via useWorkflowManager()
- Get coordinator snapshot via useCoordinatorById(workflowId)
- State: open (dropdown), confirmAction (which destructive action is pending confirmation)

- Command validity logic:
  - isRunning = snapshot?.workflowState === 'RUNNING'
  - hasExecuting = snapshot?.activeSteps.some(s => s.step.state === 'EXECUTING') ?? false
  - hasPaused = snapshot?.activeSteps.some(s => s.step.state === 'PAUSED') ?? false
  - pause: enabled when isRunning && hasExecuting
  - resume: enabled when isRunning && hasPaused
  - abandon: enabled when isRunning
  - restart: enabled when isRunning

- Command execution:
  - PAUSE: manager.getCoordinator(workflowId)?.pauseAll() -- immediate, close menu
  - RESUME: manager.getCoordinator(workflowId)?.resumeAll() -- immediate, close menu
  - ABANDON: set confirmAction = 'abandon', close dropdown, show ConfirmDialog
  - RESTART: set confirmAction = 'restart', close dropdown, show ConfirmDialog
  - On confirm ABANDON: manager.getCoordinator(workflowId)?.abort(), clear confirmAction
  - On confirm RESTART: manager.getCoordinator(workflowId)?.restart(), clear confirmAction

- Menu rendering:
  - Trigger button: EllipsisVertical icon (from lucide-react) for phone/tablet, "State Commands" text button for desktop
  - Use CSS container query classes: .dotsButton visible by default, .textButton hidden; swap at @container device-frame (min-width: 769px)
  - Dropdown: position absolute, top 100%, right 0, background white, border-radius 8px, box-shadow, z-index 50
  - Each command: full-width button, text-align left, padding 10px 16px
  - Disabled commands: opacity 0.4, cursor not-allowed
  - Destructive commands (ABANDON, RESTART): color #e74c3c when enabled
  - Close dropdown on click outside: useEffect with document.addEventListener('click', ...) when open

- Render ConfirmDialog for destructive commands:
  - ABANDON: title "Abandon Workflow?", message "This will stop and remove the workflow. This cannot be undone."
  - RESTART: title "Restart Workflow?", message "This will stop the current execution and restart from the beginning."
